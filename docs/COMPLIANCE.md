# 平台合法合规指南

适用范围：二手（二级）票务交易撮合平台，中国大陆运营。
本文把调研（见 `research/market-research-2026-09.md`）中的监管要求逐条映射到产品实现，并列出**上线前必须办妥**的事项。
性质说明：本文件为工程合规设计参考，不构成法律意见；上线前请由专业律师与税务师复核。

> 配套阅读：[LEGAL.md](LEGAL.md) —— 针对**当前社区论坛阶段**（无支付、可私聊）的司法合法性专项分析，含 2025-2026 年新修订法规（治安法、网安法）的条文核对与风险缓释建议。

## 2. 上线前必办清单（按办理顺序）

1. **市场主体登记**：注册公司（建议经营范围含"票务代理服务、互联网信息服务、数据处理"）。
2. **ICP 备案 + 增值电信业务经营许可证（ICP 证）**：经营性互联网信息服务必备；涉及在线交易的通常还需 **EDI 证**（在线数据处理与交易处理业务）。
3. **App/小程序备案**（若上架）：工信部移动互联网应用程序备案。
4. **公安联网备案**：网站上线 30 日内到全国互联网安全管理服务平台备案。
5. **支付与资金存管**：见第 3 节（这是票务平台最大的合规风险点）。
6. **营业性演出经营资质**：若平台**自营**售票（自己持票销售），平台主体须办《营业性演出许可证》；纯撮合模式下由入驻商家持证，平台审核备案即可——本平台按后者设计。
7. **与一级平台/主办方的流转合作**：强实名下"官方转赠通道"是票品过户的合法路径，需与大麦/猫眼/主办方签约或取得书面认可，避免"录入信息代拍"灰色模式。
8. **制度文件**：用户协议、隐私政策、卖家入驻协议、交易规则、退票规则、投诉处理规则（均需公示）。
9. **保险**：可考虑交易安全责任险，对冲先行赔付基金压力。

## 3. 资金合规（"二清"红线）

- **问题**：平台若以自有账户归集买家资金再结算给卖家，属于无证从事支付清算业务（"二清"），是监管明令禁止的。
- **当前阶段说明**：Fans-to-Fans 社区阶段平台**不经手任何资金**（无线上付款入口，用户自行通过官方转赠通道完成票品过户），天然无"二清"暴露；同时应在社区公约与页面中明示平台不提供站外交易担保，并持续打击引导私下转账的内容（已实现风险标记+举报隐藏）。
- **正确做法**：资金全程走持牌通道——
  - 方案 A：微信支付/支付宝的"担保交易/分账"产品，买家资金入支付机构监管户，确认收货后由支付机构按指令分账（卖家款+平台佣金）；
  - 方案 B：商业银行"电商资金存管"产品（多家银行有面向平台经济的存管方案）。
- **代码落点**：`server/api.js` 的 `pay` 路由当前是模拟托管；上线时替换为支付机构下单+异步回调，回调验签后才改订单状态。`ledger` 表结构无需变动，分账指令以支付机构回执为准。
- **先行赔付基金**：以平台自有资金单独立户（或投保），台账即 `ledger` 中 `compensation_fund` 账户。

## 4. 税务合规要点

**平台自身（以一般纳税人为例，财税中心已内置测算）：**
- 增值税：平台佣金+服务费收入按"现代服务"6%（价税分离，见 `domain.js#taxReport`）；小规模纳税人可享优惠征收率（以税务认定为准）；
- 附加税费：城建税 7%+教育附加 3%+地方教育附加 2%（按增值税额，市区口径）；
- 企业所得税：25%（应纳税所得额=不含税收入−附加税费−成本费用；小微企业有优惠）；
- 退票手续费：属于价外费用/违约金性质收入，并入计税（本平台已计入）。

**平台对卖家的义务：**
- 按 810 号令按季报送卖家身份与收入（已实现 CSV 导出）；
- 提示个人卖家依法办理市场主体登记/纳税申报（高频大额卖家建议强制转商家资质）；
- 若平台为个人卖家**代办**扣缴申报，已填报信息无需重复报送（810 号令第五条）。

## 5. 数据与隐私（PIPL）

- 身份证号属于**敏感个人信息**：单独同意、最小化收集、脱敏存储（代码已实现前 3 后 4 打码）、加密传输、留存期限到期删除；
- 实名核验须通过合法渠道（公安一所/持牌核验服务商），不得自行留存证件照片原件超期；
- 隐私政策中需明示：收集目的（强实名监管要求）、共享对象（支付机构、核验机构、监管报送）；
- 未成年人：大型演出多有年龄限制，下单时提示并核验。

## 6. 宣传与定价

- 广告法：禁用"最""第一""百分百真票"等绝对化用语（可表述为"假票先行赔付"的事实性承诺）；
- 明码标价：票价、服务费、退票手续费在下单页一次性列示（已实现）；
- 不得宣传"代拍代抢""内部渠道"等灰色服务（发布端已屏蔽此类票源选项）。

## 7. 运营期 SOP（建议固化到后台）

| 频率 | 动作 | 对应功能 |
|---|---|---|
| 每日 | 处理纠纷（24 小时内介入）、巡查溢价超限 | 纠纷处理 / 合规中心 |
| 每周 | 抽查票源凭证、复核商家资质有效期 | 票品管理 / 用户与资质 |
| 每月 | 托管资金对账（支付机构回执 vs ledger） | 财税中心（待接入支付回调后自动化） |
| 每季度次月 | 涉税信息报送（810 号令）、企业所得税预缴 | 导出 CSV / 财税中心 |
| 每年 1 月/7 月 | 市场监管部门经营者信息报送 | 用户与资质导出 |
| 每年 | ICP/EDI 年报、许可证续期检查 | 线下事项 |

> 最后强调：2026-05 起全国演出票务系统升级"一人一证一票+人脸入场+禁止转赠"（以官方文件为准）。这意味着二手流转**必须**走官方认可的通道（官方转赠/官方 resale/主办方授权的实名变更）。平台的产品设计已按"官方转赠+担保托管"建模，但实际运营前必须与票源平台/主办方取得合作，否则票品无法合法过户——这是本项目最大的商业前提，优先于一切代码工作。
