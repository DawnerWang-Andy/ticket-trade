# 票流转 · 合规二手票务交易平台（全栈 MVP）

基于国内二级票务市场调研（见 `research/`）设计：以**资金托管 + 强实名 + 官方转赠 + 价格管控（原价封顶）+ 阶梯退票 + 先行赔付**为核心的二手票务交易平台，含买家端、卖家端与平台经营后台（收入/税收/交易/合规）。

> 当前阶段：**Fans-to-Fans 粉丝票务交流论坛为主站形态（首页即社区），线上支付暂缓开通**。用户先在社区实名沟通票务（转票/求票/换票/讨论），可互留联系方式私聊，成交引导走官方转赠通道；票品展示在 `#/tickets`，担保交易功能开发完成后恢复"下单购买"。

## 粉丝社区（当前主功能）

- **四类帖子**：转票 / 求票 / 换票 / 讨论，转票帖须关联演出并填写票面价与转让价。
- **保真三板斧**：
  1. 全员实名发帖、评论公开留痕（依据《互联网跟帖评论服务管理规定》）；
  2. 转票帖可提交购票凭证，平台人工验真后展示「已验真」徽章；
  3. 发帖人可自愿公开联系方式（微信/QQ/手机）私聊，**仅实名登录用户可见**；全程引导官方转赠通道过户，资金类高危话术（定金/收款码/私下转账）自动打风险标记，支持一键举报。
- **原价封顶**：转让价不得超过票面价（仅原价/折价，细则禁止加价倒卖），超限服务端直接拦截，管理端不可调高上限。
- **法律依据常驻提示**：社区列表、发帖页、帖子详情页、票品发布页均展示《治安管理处罚法》第六十三条等条文与平台规则的对应关系。
- **后台社区管理**：验真审核、举报处理（可隐藏帖子办结）、全部帖子巡查，仪表盘含社区待办角标。

## 快速开始

```bash
# 要求 Node.js >= 22.5（使用内置 SQLite，零 npm 依赖，无需 install）
npm run seed   # 初始化演示数据（可随时重跑重置）
npm start      # 启动服务
```

- 买家端：http://localhost:8321/
- 经营后台：http://localhost:8321/admin

## 核心流程

**社区阶段（现在）**：实名认证 → 发转票/求票/换票帖（凭证验真 + 原价封顶，可附联系方式私聊）→ 公开留言或私下沟通 → 双方通过官方 App 转赠通道完成过户 → 帖子标记完结。平台不做资金经手，规避"二清"风险；私下交易风险自担。
**担保交易阶段（支付功能上线后）**：实名认证 → 选座下单（绑定观演人证件，一证一票）→ 支付（资金托管）→ 卖家官方转赠 → 确认收票（结算）/ 阶梯退票 / 发起纠纷。交易接口与订单后台已就绪，届时仅恢复前端购买入口。
**平台**：仪表盘（GMV/收入/托管/赔付基金/社区待办）→ 订单/票品/社区/用户/纠纷管理 → 合规中心 → 财税中心（增值税、附加税、企业所得税估算 + 810 号令涉税报送 CSV 导出）→ 平台设置。
